- 2026-10-11: `query-token-audit` does not cover tokenized securities. Probed `/bapi/defi/v1/public/wallet-direct/security/token/audit` on BSC (chainId 56) with real RWA contracts (e.g. IBM bStock `0xfa273b076feb8c0fb34e554ae341082323d016a3`): HTTP 200, `code: "000000"`, but `data.hasResult: false` and `data.isSupported: false`. The same endpoint answers normally for a plain BEP-20 (USDT `0x55d3...7955` returns `hasResult: true`, `isSupported: true`, `riskLevelEnum: "MID"` with populated `riskItems`). The skill's own rule is that a verdict only counts when both flags are true, so for this asset class the correct reading is "unknown", not "safe" and not "risky". Consequence: an agent that hard-blocks on a missing audit blocks every tokenized stock. We surface it as an explicit `na` check instead.
- 2026-10-11: `statusInfo.openState` is not a market-session flag. On a Saturday (US market shut) 77/488 RWA tokens still report `openState: true` with `reasonCode: "TRADING"`, while 411 report `openState: false` / `MARKET_CLOSED`. `marketStatus` carries the session value (`closed`, `offhours`) but is `null` on all 46 bStock entries, so session state has to be read from the Ondo side and absence must be treated as unknown rather than open. `nextOpenTime`/`nextCloseTime` are populated in ms and were correct (next open 2026-10-12 00:05 UTC).
- 2026-10-11: `/api/v1/dex/market/rwa/tokens` returns the same 488-token payload regardless of the `platform` query value; filtering has to be done client-side on `platformId` (442 `ondo`, 46 `bstock`). Token price must be divided by `tokenToShareRatio` to get a comparable price per share - ratios differ per issuer (e.g. SPYon 1.0095 vs SPYB 1.0017), so comparing raw `tokenPrice` across issuers invents a spread that does not exist.
